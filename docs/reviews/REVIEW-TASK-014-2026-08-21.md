## Category Checks

- **Permissions**: `SecurityConfig.kt`에 추가된 4개 규칙(`POST`/`PATCH`=TEACHER, `GET`=ADMIN+TEACHER)이 `USER_ROLES.md` 3.6과 정확히 일치. API 테스트가 관리자 작성/수정 403, 학생/학부모 403, 미인증 401을 모두 커버.
- **Domain/Architecture**: `LearningRecord`가 `studentId`만 참조하고 `lessonId`를 두지 않아 `ADR-007` Decision 4를 그대로 따름. 새로운 JPA 연관관계 없음(`ARCHITECTURE.md` §6.1 준수).
- **Data integrity**: `title`/`content` 검증이 도메인(`require`)과 프레젠테이션(`@NotBlank`/`@Size`) 양쪽에 모두 존재해 이중 방어. `update`가 두 필드를 항상 함께 받는 시그니처(둘 다 non-nullable)라 `TASK-013` 리뷰에서 발견됐던 부분 수정 데이터 유실 패턴이 구조적으로 재현되지 않음.
- **Query behavior**: `GET /api/v1/learning-records`는 `studentId`를 `@RequestParam`(필수)로 받아 누락 시 400 — 명세대로 "전체 목록 조회 없음" 제약이 지켜짐. `findAllByStudentIdOrderByCreatedAtDesc`로 정렬 조건도 명세와 일치.
- **Test coverage**: 도메인 단위(생성/수정/검증 5종)와 API 레벨(CRUD, 정렬, 타 학생 데이터 미노출, 404 4종, 400 5종, 권한 5종)이 `TASK-014` Test Scenarios 항목을 빠짐없이 커버.
- **Scope**: `git status`에 명세 밖 파일 변경 없음. `Homework`에는 있는 `findAll()`(전체 목록)을 의도적으로 두지 않은 점도 명세(Background 절 "전체 목록 조회 없음")와 일치.
