# DOMAIN_MODEL.md

# 움틀 도메인 모델

이 문서는 움틀(Umtle)의 핵심 비즈니스 도메인을 정의한다.

데이터베이스 테이블이나 구현 방식이 아니라, **비즈니스 개념·엔티티·관계·책임**을 설명하는 것을 목적으로 한다.

문서 우선순위는 `AGENTS.md`를 따르며, 이 문서는 `PRD.md`, `REQUIREMENTS.md`의 범위를 벗어나지 않는다.

---

## 1. 목적

- 움틀의 핵심 업무 개념과 그 관계를 정의한다.
- 이후 작성되는 `ARCHITECTURE.md`와 구현 설계의 기준이 되는 공통 언어(유비쿼터스 언어)를 제공한다.
- 데이터베이스 스키마, API 설계, 상태값 목록 등 구현 세부사항은 다루지 않는다.

---

## 2. 핵심 도메인 개요

움틀은 `PRD.md`의 핵심 기능을 기준으로 다음 8개의 도메인으로 구성된다.

| 도메인 | 책임 |
|--------|------|
| 사용자 (User) | 시스템을 이용하는 주체와 역할을 구분한다 |
| 학생 (Student) | 학원에 등록된 학생의 기본 정보를 관리한다 |
| 반/수업 (Class / Lesson) | 학생과 선생님을 묶는 학습 단위와 실제 수업 진행을 관리한다 |
| 일정 (Schedule) | 학원 운영 및 수업과 관련된 일정을 관리한다 |
| 출결 (Attendance) | 수업에 대한 학생의 참석 여부를 관리한다 |
| 숙제 (Homework) | 학생에게 부여되는 과제와 수행 현황을 관리한다 |
| 학습 기록 (Learning Record) | 학생의 학습 이력과 성장 과정을 누적 관리한다 |
| 공지 (Notice) | 사용자 그룹을 대상으로 한 정보 전달을 관리한다 |

---

## 3. 도메인별 상세

### 3.1 사용자 (User)

**책임**: 시스템에 접근하는 주체를 구분하고, 각 주체가 어떤 역할을 가지는지 표현한다.

- 사용자는 다음 네 가지 역할(Role) 중 하나 이상을 가진다.
  - 관리자 (Admin)
  - 선생님 (Teacher)
  - 학생 (Student)
  - 학부모 (Parent)
- 역할별 상세 권한과 접근 범위는 이 문서의 책임 범위가 아니며 `USER_ROLES.md`에서 정의한다.
- 사용자는 다른 모든 도메인에서 행위의 주체(누가 등록/조회/수정하는가) 또는 대상(누구에 대한 정보인가)으로 참조된다.
- `STUDENT` 역할을 가진 사용자는 최대 1명의 학생과 연결될 수 있고(선택적 1:1), `PARENT` 역할을 가진 사용자는 여러 학생과 연결될 수 있다(다대다) — 연결은 관리자만 생성·해제한다(`ADR-008`).

### 3.2 학생 (Student)

**책임**: 학원에 등록된 학생 개인의 정보를 관리하고, 다른 도메인이 참조할 수 있는 기준 정보를 제공한다.

- 학생은 관리자에 의해 등록·조회·수정·비활성화된다.
- 학생은 반, 수업, 출결, 숙제, 학습 기록과 연결되는 중심 엔티티다.
- 학생은 연결된 사용자 계정 없이도 독립적으로 존재할 수 있다 — 계정 연결은 선택 사항이다(`ADR-008`).
- 학생과 학부모의 연결은 다대다이며, `User`(PARENT)가 학생 id 컬렉션을 보유하는 형태로 관리한다(`ADR-008`).

### 3.3 반 / 수업 (Class / Lesson)

**책임**: 학생과 선생님을 묶는 학습 단위(반)를 관리하고, 그 반에서 실제로 진행되는 개별 수업을 관리한다.

- **반(Class)**: 학생과 선생님이 소속되는 학습 그룹. 관리자가 생성·조회·수정·비활성화하며, 학생과 선생님을 배정한다.
- **수업(Lesson)**: 반에서 실제로 진행되는 개별 수업 단위. 관리자가 생성·조회·수정·취소·완료 처리한다.
- 수업은 일정, 출결, 숙제, 학습 기록의 기준점이 된다.
- Class와 Lesson은 별도 Aggregate이며, Lesson은 Class를 `classId`로만 참조한다(`ADR-006`).
- 반-학생, 반-선생님 배정은 다대다이며 Class가 `studentIds`, `teacherIds` 순수 id 값 컬렉션으로 관리한다(`ADR-006`).
- Lesson 상태값은 `SCHEDULED`, `COMPLETED`, `CANCELLED`다(`ADR-006`).

### 3.4 일정 (Schedule)

**책임**: 학원 운영 전반과 수업에 관련된 일정을 관리하고, 사용자가 자신과 관련된 일정을 확인할 수 있도록 한다.

- 관리자는 학원 운영 일정을 등록·조회·수정·삭제한다.
- 일정은 특정 수업과 연결될 수 있다.
- 선생님은 담당 수업 관련 일정을, 학생과 학부모는 본인 또는 자녀 관련 일정을 조회할 수 있다.

### 3.5 출결 (Attendance)

**책임**: 특정 수업에 대한 학생의 참석 여부를 기록하고, 관련 사용자가 이를 조회할 수 있도록 한다.

- 출결 기록은 수업과 학생을 연결하여 생성된다.
- 선생님이 기록·수정하며, 관리자는 전체를, 학생과 학부모는 본인/자녀 기록을 조회한다.
- 출결 상태의 구체적인 종류(예: 출석/결석/지각 등)는 미정이며 이 문서에서 정의하지 않는다.

### 3.6 숙제 (Homework)

**책임**: 수업 또는 학생 단위로 부여되는 과제를 관리하고, 그 수행 현황을 추적할 수 있도록 한다.

- 선생님이 수업 또는 학생 단위로 숙제를 등록·조회·수정·삭제한다.
- 학생은 본인에게 부여된 숙제를, 학부모는 자녀의 숙제 현황을 조회한다.
- 선생님은 제출 또는 수행 상태를 확인할 수 있다.
- 숙제 상태값의 구체적인 종류는 미정이며 이 문서에서 정의하지 않는다.

### 3.7 학습 기록 (Learning Record)

**책임**: 학생별 학습 이력을 누적하여 성장 과정을 지속적으로 추적할 수 있도록 한다.

- 선생님이 학생별 학습 기록을 작성·조회·수정한다.
- 학습 기록은 시간에 따라 누적되는 형태로 존재한다.
- 관리자와 담당 선생님은 학생별 이력을 조회할 수 있다.
- 학생과 학부모에게 공개되는 범위는 권한 정책(미정)에서 정의한다.

### 3.8 공지 (Notice)

**책임**: 특정 대상(전체 또는 그룹)에게 정보를 전달하고, 사용자가 자신에게 해당하는 공지를 확인할 수 있도록 한다.

- 관리자는 전체 또는 특정 사용자 그룹을 대상으로 공지를 등록한다.
- 선생님은 담당 반 또는 학생 관련 공지를 등록한다.
- 사용자는 본인에게 해당하는 공지를 조회한다.
- 알림 채널, 발송 조건, 읽음 처리 방식은 미정이며 이 문서에서 정의하지 않는다.

---

## 4. 도메인 간 관계

```
사용자(User) ── 역할 구분 ──> 관리자 / 선생님 / 학생 / 학부모

사용자(학생 역할) ── 본인 연결(선택적 1:1) ──> 학생
학부모 ── 보호자 관계(다대다) ──> 학생

학생 ── 소속 ──> 반(Class) <── 배정 ── 선생님

반(Class) ── 진행 ──> 수업(Lesson)

수업(Lesson) ── 연결 ──> 일정(Schedule)
수업(Lesson) ── 기준 ──> 출결(Attendance) ── 대상 ──> 학생
수업(Lesson) 또는 학생 ── 부여 ──> 숙제(Homework)
학생 ── 누적 ──> 학습 기록(Learning Record)

공지(Notice) ── 대상 지정 ──> 사용자 / 반 / 학생 그룹
```

- 학생은 반·수업·출결·숙제·학습 기록 도메인이 공통으로 참조하는 중심 엔티티다.
- 수업은 일정·출결·숙제·학습 기록의 기준점 역할을 한다.
- 사용자(역할)는 모든 도메인에서 행위 주체 또는 조회 대상으로 참조된다.

## 5. 유비쿼터스 언어

| 용어 | 정의 |
|------|------|
| 사용자 (User) | 시스템에 접근하는 주체. 관리자/선생님/학생/학부모 역할을 가짐 |
| 관리자 (Admin) | 학원 운영 전반을 관리하는 역할 |
| 선생님 (Teacher) | 반과 수업을 담당하고 학생을 지도하는 역할 |
| 학생 (Student) | 학원에 등록되어 학습 활동의 대상이 되는 역할이자 핵심 도메인 엔티티 |
| 학부모 (Parent) | 학생의 보호자로서 학생 관련 정보를 조회하는 역할 |
| 반 (Class) | 학생과 선생님이 소속되는 학습 그룹 |
| 수업 (Lesson) | 반에서 실제로 진행되는 개별 수업 단위 |
| 일정 (Schedule) | 학원 운영 또는 수업과 관련된 시간 기반 정보 |
| 출결 (Attendance) | 수업에 대한 학생의 참석 여부 기록 |
| 숙제 (Homework) | 수업 또는 학생 단위로 부여되는 과제와 그 수행 현황 |
| 학습 기록 (Learning Record) | 학생의 학습 이력과 성장 과정을 나타내는 누적 정보 |
| 공지 (Notice) | 특정 대상에게 전달되는 정보 |

---

## 6. 아직 결정되지 않은 사항

다음 항목은 `REQUIREMENTS.md` 5장에 따라 아직 확정되지 않았으며, 이 문서에서도 임의로 정의하지 않는다.

- 역할별 상세 권한과 접근 범위 — `USER_ROLES.md`에 1차 정리되었으나, 일부 항목(학생 관리에서 학생·학부모 권한, 반/수업 관리 조회 권한, 숙제 관리에서 관리자 권한, 역할 간 위계 등)은 `USER_ROLES.md` 4장에 미정으로 남아 있다.
- 배정에 날짜, 승인 상태 등 부가 속성이 필요한지 여부
- 출결 상태, 숙제 상태, 수업 상태 등 상태값의 종류
- 공지 알림 채널과 발송 정책
- 학습 기록의 학생/학부모 공개 범위

> **해소된 항목**: "학부모와 학생의 연결 방식"은 `ADR-008`로 해소되어 3.1, 3.2, 4장에 반영했다.

관련 결정이 확정되면 이 문서를 갱신한다.
